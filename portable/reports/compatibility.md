## 本机模拟，而非第二台电脑实测

- 在新的临时目录模拟不同用户/安装根，包解压路径和安装路径均含中文、空格、方括号；独立安装与验证通过。
- 复制仅含虚构资源的工作目录后，从另一个启动目录重建；不依赖原工作区或原用户绝对路径。
- 独立审查补测无 Git 的空白项目，真实用户 Skill 不被误报为项目级同名；自定义安装根仍能发现真实用户的上游安装。

这些检查没有改变 Windows 登录用户，没有替换操作系统、硬件、用户权限或企业策略，也没有模拟所有 Windows 路径限制。

## 已修复的部署问题

1. 来源相对路径原先依赖启动目录：现在基于 evidence.json 父目录解析，绝对路径输出回归通过。
2. 方括号被 PowerShell 通配符解释：读取采用 LiteralPath，哈希直接用 .NET 文件 API；复杂路径复测通过。
3. py 启动器转交参数可能丢失：记录并使用探测得到的 sys.executable。
4. 自定义安装根下的上游扫描与用户级误分类：增加真实用户路径扫描并排除用户级 Reader 的项目误报。
5. PowerShell 7 经 Python 启动 5.1 时，Get-FileHash 自动加载曾失败：改为 .NET SHA-256，相关链路与负向测试已重跑通过。

## 尚未覆盖或继续保留的限制

- 第二台实体电脑、其他真实 Windows 账户、网络共享/超长路径、企业受限策略未实测。
- Python 3.9 是静态最低要求，本轮只运行 3.13.7，未逐一安装验证各版本。
- 浏览器只实测本机 Edge；不是所有浏览器版本的兼容矩阵。
- 本轮不重新解释论文、不验证新科学结论、不重新审读 PDF、不复算数据，不保证上游任意未来版本结构不变。
- 模板遗留“试点范围末尾”和 QUESTION 010 等措辞保持原样；不限制真实数据数量。
- 页面审查报告链接需要实际创建 audit/验收报告.md；构建器只输出结构校验记录，不能自动替代科学审查。
- SHA-256 清单检查完整性，不提供发布者数字签名。安装包不联网、不安装上游、不修改系统环境或全局执行策略。

在目标电脑重新运行 install.ps1 和 verify-install.ps1，并在新项目确认用户级 Skill，是跨设备部署的最终验收步骤。
